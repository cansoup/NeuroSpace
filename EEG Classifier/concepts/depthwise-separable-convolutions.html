Concept · Architecture

Depthwise-Separable Convolutions

Doing the same job with a fraction of the parameters — the core trick behind EEGNet and MobileNet.

TL;DR

A standard convolution mixes spatial patterns and channels in one expensive step. A depthwise-separable conv splits that work into two lighter ones: first a per-channel spatial filter (no channel mixing), then a 1×1 conv that mixes channels (no spatial work). Same expressive power for a small task, 5–10× fewer parameters.

The problem it solves

A standard convolution with C_in input channels, C_out output channels, and a k×k kernel has C_in × C_out × k × k parameters. Every output channel looks at every input channel everywhere in the kernel.

That's a lot of parameters. Most of them are used to learn a mix of two different jobs at once:

  1. Spatial mixing — which nearby positions to combine (the "what pattern" question)
  2. Channel mixing — which input features to combine (the "what combination of signals" question)

When you only have 90 training examples, lumping both jobs into one giant filter is a fast track to memorization. You want to split them.

How it works (the "two-step" recipe)

A depthwise-separable conv replaces one big conv with two small ones:

Step 1 — Depthwise convolution (spatial only)

Each input channel gets its own k×k filter. No cross-channel interaction. If you have 8 input channels and a 1×16 kernel, that's 8 × 1 × 16 = 128 parameters and 8 output channels (same count as input).

In PyTorch this is nn.Conv2d(C, C, kernel_size, groups=C). The groups=C argument is the trick: it splits the conv into C independent per-channel operations.

Step 2 — Pointwise convolution (channel only)

A 1×1 convolution takes the C output channels from step 1 and linearly projects them into F new output channels. No spatial work — it just looks at one position at a time and mixes the C values into F new values.

nn.Conv2d(C_in, F_out, kernel_size=1) — parameters = C_in × F_out.

The parameter savings

Say you want to transform 8 channels into 16 using a 1×16 kernel:

ApproachMathParams
Standard conv 8 × 16 × 1 × 16 2,048
Depthwise + Pointwise 8 × 1 × 16 + 8 × 16 256

Same input shape, same output shape, 8× fewer parameters. For a model trained on 90 samples, that's the difference between generalizing and memorizing.

Depthwise-separable isn't a mathematical equivalence to a full conv — the two don't produce the same output. But empirically, when the task doesn't need cross-channel mixing at every position, separating the two jobs is nearly free in accuracy and hugely cheaper in parameters. It's one of the best compression tricks in modern deep learning.

In your project

EEGNet uses depthwise convolutions in both blocks, but the second block is the textbook depthwise-separable pair: 

# Block 2 in eeg_online_classifier.py:180-188
self.block2 = nn.Sequential(
    nn.Conv2d(F1*D, F1*D, (1, 16), padding=(0, 8),
              groups=F1*D, bias=False),    # depthwise: per-channel temporal filter
    nn.Conv2d(F1*D, F2, (1, 1), bias=False),   # pointwise: 1×1 channel mixing
    nn.BatchNorm2d(F2),
    nn.ELU(),
    nn.AvgPool2d((1, 8)),
    nn.Dropout(dropout),
)

With F1=4, D=2, F2=16: 8 input channels go through an 8-way depthwise 1×16 conv (128 params), then a 1×1 conv projects to 16 (128 params). Total: 256 params for a block that a standard conv would have needed 2,048 to replicate.

Block 1's depthwise trick is slightly different

Block 1's spatial conv also uses groups — but it uses groups=F1 (not F1*D), and it expands channels (F1 → F1*D). This is a grouped conv rather than a pure depthwise. Each of the F1 temporal filters from earlier gets its own independent group of D spatial filters. The effect: the network learns D different spatial projections for each temporal feature, without letting spatial projections from different temporal features contaminate each other.

This is the specific inductive bias EEGNet brings to EEG: temporal features exist independently of spatial projections. Your mu-band filter shouldn't need to know what the beta-band filter saw, until the later mixing step.

Where else you see this trick

  • MobileNet (Google, 2017) — built entire vision models from depthwise-separable blocks to run on phones. Same math, same savings, different domain.
  • Xception (Chollet, 2017) — argued depthwise-separable is a strictly better building block than standard conv for most tasks.
  • EEGNet (Lawhern et al., 2018) — adapted the idea to EEG, exploiting the spatial-vs-temporal separation naturally present in the data.

Pitfalls

Not every task likes it. For tasks where cross-channel interactions at every spatial position are genuinely needed (e.g. some high-frequency image classification), separable convs can lose accuracy. For EEG, where frequency and space are largely separable, the tradeoff is free lunch.

Depthwise is slow on old GPUs. Depthwise convs are memory-bound rather than compute-bound, and until recently some GPU kernels weren't optimized for them. Modern PyTorch on recent GPUs handles them fine; on CPU (where your online classifier runs), they're cheap either way.

Interview-ready answer

EEGNet's second block is a depthwise-separable convolution. A standard conv does spatial filtering and channel mixing at the same time, which is parameter-expensive. Depthwise-separable splits the work: first a per-channel temporal filter with groups=C, then a 1×1 conv that mixes channels. For my 8-to-16 channel transformation, that's 256 parameters instead of 2,048 — an 8× reduction. The inductive bias — spatial and channel mixing can be learned separately — matches EEG well, where temporal dynamics exist largely independent of electrode layout.

Going deeper (if they push)

  • Grouped convolution: the generalization. Depthwise is groups = C_in; standard is groups = 1; grouped conv is anything in between. ResNeXt and ShuffleNet exploit this middle ground.
  • Channel shuffle (ShuffleNet): if you stack many grouped convs, information gets stuck within groups. A cheap channel-shuffle layer between them fixes it.
  • 1×1 convs as "network-in-network": pointwise convs were popularized by the original NiN paper and GoogLeNet's inception blocks. They're also the entire architecture of ResNet's bottleneck blocks.
