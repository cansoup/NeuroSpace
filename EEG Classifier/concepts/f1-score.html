Concept · Evaluation metric

F1 Score

Why accuracy lies, and how precision and recall tell the truth.

TL;DR

Accuracy asks "how often are you right overall?" but a model that always predicts the majority class can ace that question without learning anything. F1 combines precision (quality of your "yes" predictions) and recall (how many real "yes" cases you caught) into a single number that punishes models for being lazy.

The problem accuracy can't solve

Suppose you're screening for a rare disease that 1% of people have. A model that predicts "healthy" for everyone has 99% accuracy and catches exactly zero sick patients. Technically correct. Clinically useless.

Your EEG dataset isn't that extreme — classes are roughly balanced — but the same failure mode applies more subtly. Imagine "both hands" trials are slightly harder to decode. A model could quietly give up on that class, nail the easier two, and still post a reasonable accuracy number. You'd never know from accuracy alone that one-third of your system doesn't work.

The building blocks: precision and recall

Pick one class — say "left hand." For that class, every prediction is either right or wrong, and every real "left hand" trial is either caught or missed. Four outcomes:

Actually left
Actually not left
Predicted left
True positive
False positive
Predicted not left
False negative
True negative

Precision = of my "left" predictions, how many were actually left?
precision = TP / (TP + FP)

Recall = of all the real "left" trials, how many did I catch?
recall = TP / (TP + FN)

They trade off. A spam filter that flags only the obviously-spammy emails has high precision (few false alarms) but low recall (lots of spam gets through). A filter that flags anything remotely suspicious has high recall but low precision (you're fishing real email out of spam every morning).

F1: one number that punishes imbalance

You could report precision and recall separately. But when comparing 12 hyperparameter configurations, you want one number to rank them by. The obvious move — average precision and recall — is a trap: a model with precision 1.0, recall 0.0 would score 0.5, the same as a balanced precision 0.5, recall 0.5 model.

F1 uses the harmonic mean instead: 

F1 = 2 × (precision × recall) / (precision + recall)

The harmonic mean is dragged down by whichever number is smaller. Precision 1.0 with recall 0.0 gives F1 = 0 — exactly the grade it deserves. You can't win F1 by doing only half the job.

Macro-F1 vs micro-F1 vs weighted-F1

You have three classes, so you get three F1 scores (one per class). How do you combine them?

FlavorHow it aggregatesProperty
Macro-F1 Simple average of per-class F1 scores Treats every class as equally important. Rewards balanced performance.
Micro-F1 Pools TP/FP/FN across all classes, then computes one F1 For multi-class, mathematically equals accuracy. Not useful here.
Weighted-F1 Per-class F1 weighted by class size Biases toward majority classes. Hides weakness on minority classes.

You chose macro-F1. It's the right metric for the job: you care that the model works for all three motor-imagery classes, not just the one with the most trials. A model that's great on "left" and "right" but terrible on "both" should lose to a model that's mediocre on all three — and macro-F1 enforces that.

In your project

From notebooks/utils/eval.py: 

from sklearn.metrics import f1_score, precision_score, recall_score

macro_f1 = f1_score(y_true, y_pred, average='macro', zero_division=0)
per_class_f1 = f1_score(y_true, y_pred, average=None)   # array of 3 values

The per-class F1 array is where debugging happens. If macro-F1 is 0.62 and per-class is [0.75, 0.72, 0.39], you immediately know the model is struggling on the third class and can look at the confusion matrix to see what it's confusing it with.

The zero_division=0 argument handles a corner case: if the model never predicts a class at all during a fold, precision is undefined (0/0). zero_division=0 tells sklearn to return 0 instead of crashing.

Pitfalls

F1 ignores true negatives. It's a metric about how well you identify the positive class, not how well you identify the negative one. For a balanced multi-class problem this is fine; for skewed binary problems (like anomaly detection) you might also want specificity or AUC.

Comparing F1 across datasets is meaningless. A 0.65 macro-F1 on your 3-class EEG data isn't comparable to 0.65 on 10-class ImageNet. Always compare against chance (1/3 ≈ 0.33 here) and against the same evaluation protocol.

Macro-F1 penalizes small classes harder. If a class has 5 trials and you miss 1, recall drops from 1.0 to 0.8 — a huge swing that'll tank the macro average even if overall performance is fine. If classes are very imbalanced, consider whether that sensitivity is what you want, or switch to weighted-F1.

Interview-ready answer

I selected on macro-F1 rather than accuracy. Accuracy can be gamed by a model that ignores the harder classes, which is a real risk in a 3-class motor-imagery setup. Macro-F1 is the unweighted average of per-class F1 — the harmonic mean of precision and recall for each class — so a model that quietly fails on one class gets penalized. I also log per-class F1 and the full confusion matrix so I can see exactly which class is struggling and what it's being confused with.

Going deeper (if they push)

  • F-beta: generalizes F1 by letting you weight precision and recall differently. F0.5 emphasizes precision; F2 emphasizes recall. Choose based on which error is more costly.
  • Cohen's kappa: like accuracy but adjusted for chance agreement. Useful when chance performance is high (e.g. 2-class balanced).
  • Matthews Correlation Coefficient (MCC): uses all four confusion-matrix cells including TN. Often considered the most robust single-number binary classification metric.
  • Balanced accuracy: simple average of per-class recall. A common alternative to macro-F1 when you don't care about precision (e.g. screening tests).
