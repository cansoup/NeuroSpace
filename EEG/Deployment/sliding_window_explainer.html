The Rolling EEG Buffer

The script reads EEG samples from the OpenBCI headset continuously at 250 samples/second across 8 channels. These land in a rolling buffer that holds the last 15 seconds of data (~3,750 samples). Old samples fall off the left as new ones arrive on the right.

EEG buffer — newest samples arriving →
← 15 s ago (oldest) now (newest) →
Why 15 seconds?
We only need the last 8 seconds to run the model. Keeping 15 gives us breathing room so there's always a full window available even if the inference loop is slightly behind.

Snapping a Window Every 500 ms

Every 500 milliseconds, the script pauses the stream, reaches back into the buffer, and grabs the most recent 8 seconds of data. This is one window. Then it resumes.

15-second buffer — window slides forward in time →
← 8 s window →
window advances every 500 ms
Window size
8 seconds × 250 Hz × 8 channels
= 2,000 samples per channel
(rounded up to 2,001 in code)
Slide interval
500 ms = 2 windows per second
The buffer is almost always full,
so windows overlap significantly.

What's Inside the 8-Second Window

The model was trained on 4-second epochs. The extra 2 seconds on each side are padding — real EEG, not silence. Here is why that matters.

Why the padding?
The 8–30 Hz bandpass filter (mu/beta rhythms) causes ringing at the start and end of whatever signal you hand it — the first and last ~2 seconds of a filtered window look distorted. By wrapping the real 4-second epoch in 2 seconds of genuine EEG on each side, we filter the full 8 seconds and then slice out only the clean middle 4 seconds to feed the model.

The Model Classifies the Epoch

The EEG Conformer (a transformer-based neural network) takes the 4-second, 8-channel epoch and outputs a probability for each class. The three probabilities always add up to 100%.

Debounce — Two Wins in a Row

A single confident window is not enough to fire. The same class must win 2 consecutive windows, each above its threshold. This kills spurious spikes.

Per-Class Thresholds

Different motor imagery patterns are not equally easy to classify. Each class has its own threshold tuned to how confidently the model can recognise it.

Class Threshold Why this value
LEFT 60% Fires reliably at ~70–80% in testing. Lowered slightly from 75% because LEFT imagery gives moderate confidence, not sky-high.
RIGHT 75% The model's strongest class — peaks at 92–99% confidence in live tests. Kept at 75% to demand real intent, not lucky spikes.
BOTH 45% Bilateral (both hands) imagery is the hardest pattern to isolate. The model rarely exceeds 60% for BOTH, so a lower threshold is needed to let any BOTH commands through at all.
These values were set after a live test of 143 commands where BOTH never fired once at 75%. The lesson: tune thresholds per class rather than using a single global value.
8 / 10

Cooldown — 3 Seconds of Silence

After a command fires, the system ignores all windows for 3 seconds. This prevents one mental gesture from triggering a rapid burst of repeated commands.

Timeline after a command fires:
FIRE
🔒 cooldown — no commands (3 s)
✓ next command allowed
t = 0 s t = 1 s t = 2 s t = 3 s t = 4 s →
During cooldown, EEG is still collected and the buffer still fills normally. Inference still runs — the cooldown check simply discards any fire events before broadcasting. Nothing is missed; you can start a new gesture immediately and it will land cleanly after 3 s.

End-to-End Timeline

From the moment you start imagining to the moment the command arrives on the Apple Vision Pro — best case ~1 second.

t = 0 s

You start imagining

Motor imagery begins. The mu rhythm (8–12 Hz) starts suppressing over the contralateral motor cortex. The buffer continues filling at 250 Hz.

t = 0.5 s

Window 1 is snapped and classified

The inference loop wakes up, grabs the last 8 s, bandpass-filters, slices the middle 4 s, runs the EEG Conformer. Result: e.g. LEFT 72%. Debounce counter: 1/2.

t = 1.0 s

Window 2 confirms — command fires!

A second window, 500 ms later, also returns LEFT above 60%. Debounce satisfied. The script enqueues "LEFT" and prints [FIRE #1] LEFT p=0.72.

t = 1.0 s

WebSocket broadcast

The bridge thread picks up the queued command and sends {"class":"left","prob":0.72,"count":1} over the local network to all connected WebSocket clients.

t ≈ 1.0 s

Apple Vision Pro acts

The visionOS app receives the JSON, reads class: left, and executes whatever action is mapped to LEFT — object selection, navigation, etc.

Worst case: if the first few windows are just below threshold, the debounce streak never starts until the imagery strengthens. Typical latency in practice: 1–2.5 seconds from onset of imagination to command landing.

What Happens When You're Just Sitting There

The model is a 3-class softmax — it always picks a winner. When your brain is doing nothing special, probabilities hover near 33% each. The threshold and debounce absorb that noise.

Typical output at rest — brain activity looks "random"
LEFT
38%
RIGHT
29%
BOTH
33%
Even LEFT "wins" at 38%, it is still well below its 60% threshold. The debounce streak never starts. No command fires.
Safety net summary: threshold blocks single-window noise · debounce blocks lucky streaks · cooldown blocks bursts
Long-term improvement: training a 4th "rest" class would teach the model to explicitly output high probability on doing-nothing brain activity, making the system even more selective.
